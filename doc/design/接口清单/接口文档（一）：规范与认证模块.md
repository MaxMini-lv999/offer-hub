# 接口文档（一）：规范与认证模块

本文档定义接口通用规范，并列出认证模块和用户信息模块的完整接口。

## 通用规范

### 响应格式

所有接口统一返回以下 JSON 结构。`code` 为 500（服务器内部错误）时 HTTP 状态码为 500，`code` 为 429（请求过于频繁）时 HTTP 状态码为 429，其余情况（成功，以及 400 / 401 / 403 等业务错误）HTTP 状态码均为 200：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {}
}
```

`code` 为 0 表示成功，非 0 表示失败。`msg` 是人类可读的描述。`data` 是业务数据，失败时为 `null`。

### 错误码

|code|含义|
|---|---|
|`0`|成功|
|`400`|参数错误|
|`401`|未认证（token 无效或已过期）|
|`403`|无权限|
|`429`|请求过于频繁（限流）|
|`500`|服务器内部错误|

### 时间格式

所有接口返回的时间字段（`create_time`、`update_time` 等）都是北京时间（UTC+8），格式 `YYYY-MM-DD HH:mm:ss`，与服务器所在的时区无关。

### 认证方式

需要登录的接口，在请求头中携带 JWT token：

```Plaintext
Authorization: Bearer <token>
```

### 鉴权模式

项目有两种鉴权模式：

- **强制鉴权**：没有有效 token 直接返回 `code: 401, msg: "未登录或登录已过期"`，用于必须登录才能操作的接口，比如发表评论、点赞。token 缺失、格式不对（必须是 `Bearer ` 前缀，大小写敏感）、签名错误、已过期、已登出都按这种情况处理；查黑名单时 Redis 出错返回 `code: 500`，不放行。token 校验通过后还会按 `user_id` 查一次用户表：用户已不存在同样返回 `code: 401, msg: "未登录或登录已过期"`；账号不是正常状态（`user_status` 不为 1，比如签发 token 之后被禁用）返回 `code: 401, msg: "账号不可用"`；查库出错返回 `code: 500`。软鉴权不查用户表。

- **软鉴权**：有 token 就解析用户信息，没有 token 也放行。用于游客和登录用户都能访问、但返回数据不同的接口，比如题目详情。游客访问时 `content` 截断至前150字，`analysis_content` 置空；登录用户返回完整内容，并附加 `user_liked`、`user_tag` 字段。

### 限流

所有已注册的接口都有限流，固定窗口计数，窗口长度和上限读配置 `[RateLimit]`（`window_seconds` / `max_requests`，`enable = false` 时关闭；开启时两者必须大于 0，否则启动失败）。超过上限返回 HTTP 429，响应体为 `code: 429, msg: "请求过于频繁，请稍后再试"`。

- **计数对象**：带有效 token 的请求按 `user_id` 计数，其余（游客、注册、登录）按客户端 IP 计数。`user_id` 只取 JWT 校验后的值，请求头里的 `user_id` 一律忽略；客户端 IP 取 TCP 连接的对端地址，不信任 `X-Forwarded-For` / `X-Real-IP`（部署到反向代理后面时需要在 `ngin` 里配置可信代理）。
- **计数范围**：同一个用户（或 IP）的计数在所有接口之间共享，不按接口分开。
- **顺序**：先鉴权后限流。强制鉴权接口 token 无效时直接返回 401，不计数。
- **Redis 出错**：放行并记录日志，不因限流不可用而拒绝请求（与黑名单校验的「出错不放行」相反）。
- **Redis key**：`rate_limit:<user:{user_id} | ip:{ip}>:<窗口号>`，窗口号 = Unix 秒数 / 窗口秒数，TTL = 窗口长度 + 1 秒。
- **登录、注册额外限流**：`POST /auth/login` 和 `POST /auth/register` 在上面的全站限流之外，再按客户端 IP 单独计数，读配置 `[AuthRateLimit]`（字段同 `[RateLimit]`，默认 60 秒 10 次；配置文件里没有这一段时按默认值开启，要关闭需显式写 `enable = false`）。两个接口共用一个计数，超过上限同样返回 HTTP 429。这层限流排在全站限流前面，被它拦下的请求不占全站限流的额度。Redis key 为 `rate_limit:auth:ip:{ip}:<窗口号>`。

## 认证模块

### POST /auth/register 注册

**鉴权**：无需登录

**请求体**：

```JSON
{
  "username": "testuser",
  "password": "123456"
}
```

|参数|类型|必填|说明|
|---|---|---|---|
|`username`|string|是|用户名，最长50字符，不能为空|
|`password`|string|是|密码，最少6位|

**响应**：

```JSON
{
  "code": 0,
  "msg": "注册成功",
  "data": null
}
```

**错误情况**：用户名已存在返回 `code: 500, msg: "用户名已存在"`；参数不合法返回 `code: 400, msg: "用户名或密码不符合要求"`。

### POST /auth/login 登录

**鉴权**：无需登录

**请求体**：

```JSON
{
  "username": "testuser",
  "password": "123456"
}
```

**响应**：

```JSON
{
  "code": 0,
  "msg": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "userInfo": {
      "userId": "abc123",
      "username": "testuser",
      "nickName": "测试用户",
      "avatar": "https://example.com/avatar.jpg",
      "sex": 1,
      "vip": false,
      "phone": "",
      "email": "",
      "userStatus": 1,
      "userType": 1
    }
  }
}
```

注意 `userInfo` 字段使用 camelCase 命名，与其他接口的 snake\_case 不同。

**错误情况**：参数不合法返回 `code: 400, msg: "用户名或密码不符合要求"`；用户名不存在或密码错误统一返回 `code: 400, msg: "用户名或密码错误"`，不区分两种情况，防止通过登录接口探测用户名是否已注册；密码校验通过但账号不是正常状态（`user_status` 不为 1，目前只有 -1 禁用）返回 `code: 403, msg: "账号已被禁用"`。同一 IP 登录、注册合计超过限额返回 HTTP 429（见「限流」）。

### POST /auth/logout 登出

**鉴权**：强制登录

**请求头**：`Authorization: Bearer <token>`

**请求体**：无

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "message": "登出成功"
  }
}
```

登出后 token 写入 Redis 黑名单，TTL 等于 token 剩余有效期。黑名单中的 token 再次请求会返回 401。

### GET /api/v1/user\_info/get\_user\_info 获取用户信息

**鉴权**：强制登录

**请求头**：`Authorization: Bearer <token>`

**请求参数**：无。查询哪个用户由 token 里的 `user_id` 决定（鉴权中间件验签后写入 context），不从请求参数或其他请求头读取，防止伪造。

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "user_id": "abc123",
    "username": "testuser",
    "nick_name": "测试用户",
    "avatar": "https://example.com/avatar.jpg",
    "vip": false,
    "sex": 1,
    "phone": "",
    "email": "",
    "introduction": "",
    "avatar_url": "https://example.com/avatar.jpg",
    "user_status": 1,
    "user_type": 1,
    "create_time": "2024-01-01 12:00:00",
    "update_time": "2024-01-01 12:00:00"
  }
}
```

`avatar_url` 与 `avatar` 取值相同（表中只有 `avatar` 一列）。时间为北京时间，格式 `YYYY-MM-DD HH:mm:ss`。账号不是正常状态（比如已禁用）时被强制鉴权拦下，返回 `code: 401, msg: "账号不可用"`，不返回资料。

**错误情况**：token 无效按强制鉴权规则返回 `code: 401`；token 有效但对应用户已不存在，同样返回 `code: 401, msg: "未登录或登录已过期"`；账号不是正常状态返回 `code: 401, msg: "账号不可用"`；数据库出错返回 `code: 500, msg: "服务器内部错误"`。

### GET /home 首页数据

**鉴权**：无需登录

**请求参数**：无

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "hot_questions": [
      {
        "question_id": "q001",
        "title": "什么是 Redis 的持久化机制？",
        "view_count": 1024
      }
    ]
  }
}
```
