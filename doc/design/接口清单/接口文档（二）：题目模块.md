# 接口文档（二）：题目模块

本文档列出题目模块的完整接口。所有接口的通用规范（响应格式、错误码、鉴权方式）见接口文档（一）。

题目模块的接口分为两类：题目查询接口使用软鉴权，游客和登录用户都能访问；标记掌握状态的接口使用强制鉴权，必须登录。

## GET /api/v1/question/all/list 题库全量列表

**鉴权**：软鉴权

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`job_name`|string|否|职位方向过滤，如后端开发、前端开发、AI开发|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": [
    {
      "job_name": "后端开发",
      "series_list": [
        {
          "series_id": "s001",
          "series_name": "数据库",
          "order": 1,
          "bank_list": [
            {
              "bank_id": "b001",
              "bank_name": "MySQL题库",
              "bank_logo": "https://example.com/mysql.png",
              "desc": "MySQL核心知识点",
              "count": 120,
              "order": 1
            }
          ]
        }
      ]
    }
  ]
}
```

返回结构按职位方向分组，每个方向下包含系列列表，每个系列下包含题库列表。`count` 是该题库下的题目数量。

## GET /api/v1/question/list 题目列表

**鉴权**：软鉴权

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`bank_id`|string|否|题库 ID 过滤|
|`keyword`|string|否|关键词搜索，匹配标题和内容；按空白（含全角空格）拆成多个词，每个词都要命中；最多 50 个字|
|`difficulty`|int|否|难度过滤：1简单 / 2中等 / 3困难|
|`tags`|\[\]string|否|标签过滤，支持多个|
|`job_name`|string|否|职位方向过滤|
|`user_tag`|int|否|掌握状态过滤：1已掌握 / 2晚点再刷 / 3未掌握，需要登录|
|`sort_by`|string|否|排序字段：order（默认）/ create\_time / view\_count / thumbs\_up\_count / dislike\_count|
|`sort_order`|string|否|排序方向：asc / desc；不传时 order 默认 asc，其余字段默认 desc|
|`page`|int|否|页码，默认 1；最多翻到跳过 10000 条，即 `(page - 1) * page_size ≤ 10000`|
|`page_size`|int|否|每页数量，默认 20，最大 100（超过按 100 处理）|

**参数规则**：

- `page` / `page_size` 不传或 ≤ 0 时取默认值。页码超出总页数时 `list` 为 `[]`，`total` 不变。
- 排序值相同的题按 `_id` 兜底排序，方向与 `sort_order` 相同，翻页不重不漏。
- `keyword` 首尾空白会去掉，全是空白时当作没传。匹配不区分大小写，按字面匹配，`.`、`*` 等不当作正则。
- 参数不合法返回 `code: 400, msg: "参数错误"`：`sort_by` 不在上面的列表里，`sort_order` 不是 asc / desc（区分大小写），`page` 超出上限，`keyword` 超过 50 个字或含有 `\x00`、非法 UTF-8，`user_tag` 不在 0~3。
- `user_tag` 传 0 或不传表示不按掌握状态过滤。登录用户传 1~3 时只返回自己标成这种状态的题，可以和其他过滤条件一起用；没有这种标记的题时 `total` 为 0、`list` 为 `[]`。

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "total": 100,
    "list": [
      {
        "question_id": "q001",
        "bank_list": ["b001", "b002"],
        "title": "什么是 Redis 的持久化机制？",
        "content": "Redis 提供了两种持久化方式...",
        "difficulty": 2,
        "tags": ["Redis", "数据库"],
        "status": 1,
        "vip": false,
        "hot_degree": 85,
        "view_count": 1024,
        "thumbs_up_count": 256,
        "dislike_count": 12,
        "order": 1,
        "user_tag": 0,
        "user_liked": false,
        "create_time": "2024-01-01 12:00:00",
        "update_time": "2024-01-01 12:00:00"
      }
    ]
  }
}
```

游客访问时，每条题目的 `content` 截断至前150字。`user_tag` 和 `user_liked` 返回零值。

登录用户返回完整内容，`user_tag` 和 `user_liked` 反映当前用户的实际状态。

`user_tag` 过滤参数只对登录用户有效，游客传入 1~3 会被忽略（传其他值仍然返回参数错误）。目前登录用户的列表内容也按游客返回（`content` 截断、`user_tag` / `user_liked` 为零值），只有 `user_tag` 过滤生效。

## GET /api/v1/question/meta/list 题目元数据列表

**鉴权**：软鉴权

**请求参数**：与 `/api/v1/question/list` 相同，支持全部过滤和排序参数。

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "total": 100,
    "list": [
      {
        "question_id": "q001",
        "title": "什么是 Redis 的持久化机制？"
      }
    ]
  }
}
```

只返回题目 ID 和标题，用于题目导航侧边栏。不包含内容字段，响应体积小。

## GET /api/v1/question/detail 题目详情

**鉴权**：软鉴权

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`question_id`|string|是|题目 ID|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "question_id": "q001",
    "bank_list": ["b001"],
    "title": "什么是 Redis 的持久化机制？",
    "content": "Redis 提供了两种持久化方式...",
    "difficulty": 2,
    "tags": ["Redis", "数据库"],
    "status": 1,
    "vip": false,
    "hot_degree": 85,
    "view_count": 1024,
    "thumbs_up_count": 256,
    "dislike_count": 12,
    "order": 1,
    "user_tag": 1,
    "user_liked": true,
    "create_time": "2024-01-01 12:00:00",
    "update_time": "2024-01-01 12:00:00",
    "analysis_content": "RDB 是定时快照，AOF 记录每条写命令..."
  }
}
```

比列表多一个 `analysis_content`（题目解析）字段。

游客访问时，`content` 截断至前150字，`analysis_content` 为空字符串，`user_liked` 和 `user_tag` 返回零值。

登录用户返回完整的 `content` 和 `analysis_content`，并附加 `user_liked` 和 `user_tag` 的实际值：`user_liked` 只认未取消的点赞（`user_interactions` 里 `target_type=1`、`interaction_type=1`、`status=1`），没标记过的题 `user_tag` 为 0。查询这两个状态失败时返回 `code 500`。

`user_id` 由软鉴权从 token 中解析，不从请求头读取。

## GET /api/v1/question/hot/list 热门题目列表

**鉴权**：软鉴权

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`limit`|int|否|返回数量，默认 10|
|`job_name`|string|否|职位方向过滤|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "list": [
      {
        "question_id": "q001",
        "bank_list": ["b001"],
        "title": "什么是 Redis 的持久化机制？",
        "view_count": 1024
      }
    ]
  }
}
```

按 `hot_degree` 降序排列，只返回 ID、标题和浏览数，用于首页和热门题目页展示。

## GET /api/v1/question/random/list 随机题目列表

**鉴权**：软鉴权

用于沉浸式刷题的推荐模式：把全部正常题目按随机种子打乱后分页返回，只有 ID 和标题。

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`seed`|int|否|随机种子。同一个种子顺序固定，翻页时带上它；不传或 ≤ 0 时由服务端生成|
|`page`|int|否|页码，默认 1；最多翻到跳过 10000 条，即 `(page - 1) * page_size ≤ 10000`|
|`page_size`|int|否|每页数量，默认 20，最大 50（超过按 50 处理）|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "seed": 8854540181209867,
    "total": 30,
    "list": [
      {
        "question_id": "q119",
        "title": "Go 的 map 是并发安全的吗？"
      }
    ]
  }
}
```

**规则**：

- 每道题的位置由 `SHA-256(seed + ":" + question_id)` 的前 8 字节决定，按它从小到大排。同一个种子的各页拼起来正好是全部正常题目，不重不漏；新增或下线一道题只是在顺序里插进或抽掉它，其他题的先后不变。
- `seed` 是这次用的种子，客户端没传时也会返回生成的那个，范围 1 ~ 2^53，JavaScript 的整数能精确表示。
- `total` 是正常题目总数。页码超出总页数时 `list` 为 `[]`，`total` 不变。
- 参数不合法返回 `code: 400, msg: "参数错误"`：`seed`、`page`、`page_size` 不是整数，`page` 超出上限。

## GET /api/v1/question/tag/list 标签列表

**鉴权**：软鉴权

统计正常题目用到的标签和每个标签的题目数，用于沉浸式刷题按标签选题。

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`bank_id`|string|否|只统计这个题库的题，不传则统计全部|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "list": [
      { "tag": "Go", "count": 10 },
      { "tag": "MySQL", "count": 6 }
    ]
  }
}
```

按题目数从多到少排，一样多的按标签名排。`count` 与 `/api/v1/question/list?tags=<标签>` 的 `total` 一致（同一 `bank_id` 下）。题库不存在或没有题时 `list` 为 `[]`。

## POST /api/v1/safe/tag\_question 标记题目掌握状态

**鉴权**：强制登录

**请求体**：

```JSON
{
  "question_id": "q001",
  "tag": 1
}
```

|参数|类型|必填|说明|
|---|---|---|---|
|`question_id`|string|是|题目 ID|
|`tag`|int|是|掌握状态：0未标记 / 1已掌握 / 2晚点再刷 / 3未掌握|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": null
}
```

对同一题目重复标记时执行 upsert，更新已有记录。传入 `tag: 0` 表示取消标记，记录保留，`tag` 写为 0。

当前用户取自 token，不读请求头或请求体里的 `user_id`。

**错误情况**：参数不合法（缺 `question_id`、缺 `tag`、`tag` 不在 0~3）返回 `code: 400, msg: "参数错误"`；题目不存在、已隐藏或已删除返回 `code: 400, msg: "题目不存在"`；数据库出错返回 `code: 500, msg: "服务器内部错误"`。
