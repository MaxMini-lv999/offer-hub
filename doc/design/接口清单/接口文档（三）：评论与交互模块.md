# 接口文档（三）：评论与交互模块

本文档列出评论模块和用户交互模块的完整接口。通用规范见接口文档（一）。

评论列表使用软鉴权，游客和登录用户都能访问。发表、删除、修改评论需要强制登录。点赞和取消点赞也需要强制登录。

**敏感词过滤**：发表评论和修改评论用同一套规则。`content` 先去掉首尾空白，再把命中词库的词替换成等长的 `*`（按字符数算，如 `你是傻逼吧` → `你是**吧`），含敏感词不会导致请求被拒绝。词库是 `backend/src/sensitive_words.txt`，一行一个词，路径和检查间隔见配置 `[Sensitive]`。服务运行中改这个文件不用重启，默认 5 秒内生效。改出来的内容不合法（文件不存在、不是 UTF-8、一个词都没有）时，继续用上一版本。已经发出去的评论不会按新词库重新过滤，修改评论时才按当时的词库过滤。

## GET /api/v1/open/list\_comments 评论列表

**鉴权**：软鉴权

**请求参数**：

|参数|类型|必填|说明|
|---|---|---|---|
|`target_type`|int|是|评论对象类型：1题目 / 2面经|
|`target_id`|string|是|评论对象 ID|
|`parent_id`|string|否|父评论 ID，为空时返回顶层评论列表，不为空时返回该评论的子评论列表|
|`sort_by`|string|否|排序字段：create\_time / view\_count / thumbs\_up|
|`sort_order`|string|否|排序方向：asc / desc|
|`page`|int|否|页码，默认 1|
|`page_size`|int|否|每页数量，默认 20|
|`sub_comment_page`|int|否|子评论页码，默认 1|
|`sub_comment_size`|int|否|子评论每页数量，默认 5|

**响应**：

`parent_id` 不为空时，接口只返回该父评论下的子评论列表，不再嵌套 `sub_comments`。

```JSON
{

  "target_id": "q001",
  "parent_id": "",
  "reply_to": "",
  "content": "这道题解析写得很清楚"

```

|参数|类型|必填|说明|

## POST /api/v1/comment/delete 删除评论

**鉴权**：强制登录

**请求体**：

```JSON
{
  "comment_id": "c001"
}
```

**响应**：

```JSON
{
  "code": 0,
  "msg": "success"
}
```

软删除，将评论 `status` 更新为 5。只能删除自己的评论，删除他人评论返回 `code: 403`。

当前用户取自 token，不读请求头或请求体里的 `user_id`。删除回复时，父评论的 `child_count` 减 1；删除顶层评论不影响其下的回复。

**错误情况**：参数不合法返回 `code: 400, msg: "参数错误"`；评论不存在、已删除或不是正常状态（审核中等）返回 `code: 400, msg: "评论不存在"`，重复删除同一条也是这个结果；删除他人评论返回 `code: 403, msg: "只能删除自己的评论"`；数据库出错返回 `code: 500, msg: "服务器内部错误"`。

## POST /api/v1/comment/update 修改评论

**鉴权**：强制登录

**请求体**：

```JSON
{
  "comment_id": "c001",
  "content": "修改后的评论内容"
}
```

|参数|类型|必填|说明|
|---|---|---|---|
|`comment_id`|string|是|评论 ID|
|`content`|string|是|修改后的内容，经过敏感词过滤|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "comment_id": "c001"
  }
}
```

只能修改自己的评论，修改他人评论返回 `code: 403`。

当前用户取自 token，不读请求头或请求体里的 `user_id`。`content` 去掉首尾空白后过滤敏感词再写入，最长 1000 字；`update_time` 同时更新为当前时间。被禁用的账号不能修改评论。

**错误情况**：参数不合法（含 `content` 全为空白）返回 `code: 400, msg: "参数错误"`；评论不存在、已删除或不是正常状态（审核中等）返回 `code: 400, msg: "评论不存在"`；修改他人评论返回 `code: 403, msg: "只能修改自己的评论"`；token 有效但用户已不存在返回 `code: 401, msg: "未登录或登录已过期"`；账号不是正常状态（被禁用等）按强制鉴权规则返回 `code: 401, msg: "账号不可用"`；数据库出错返回 `code: 500, msg: "服务器内部错误"`。

## GET /api/v1/comment/user/liked\_collected\_count 获取被点赞数

**鉴权**：强制登录

**请求参数**：无

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "liked_count": 42,
    "collected_count": 0
  }
}
```

统计当前登录用户所有评论被点赞的总数。`collected_count` 当前始终为 0，项目不支持收藏功能。

## POST /api/v1/interaction/like 点赞

**鉴权**：强制登录

**请求体**：

```JSON
{
  "target_type": 1,
  "target_id": "q001"
}
```

|参数|类型|必填|说明|
|---|---|---|---|
|`target_type`|int|是|目标类型：1题目 / 3评论（2面经本期无，传 2 返回参数错误）|
|`target_id`|string|是|目标 ID|

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "liked": true,
    "count": 257
  }
}
```

`liked` 表示操作后的点赞状态，`count` 是目标当前的总点赞数。前端以这两个值为准校准缓存。

**点赞数来源**：点赞数只有一个来源，就是目标上的计数字段，题目是 `question.thumbs_up_count`，评论是 `comments.thumbs_up`。题目列表、题目详情、评论列表和点赞 / 取消点赞接口返回的点赞数都读这个字段。`user_interactions` 只决定谁点过赞（`liked` / `user_liked`），不参与计数。计数字段只在点赞状态真的翻转时用 `$inc` 原子加减，服务端不做 ±1 估算：状态变了时，`count` 取 `$inc` 之后的值；状态没变（重复点赞、没点过赞就取消）时，取写点赞记录之前读到的值。

当前用户取自 token，不读请求头或请求体里的 `user_id`。点赞记录按 `user_id + target_type + target_id + interaction_type` upsert 进 `user_interactions`，`status` 置为 1。接口是幂等的：只有点赞状态从无到有（没有记录或 `status` 为 0）时，目标的点赞数才加 1，重复点赞直接返回当前点赞数。题目的点赞数字段是 `question.thumbs_up_count`，评论的是 `comments.thumbs_up`。

同一用户并发重复点赞时，数据库里只会有一条记录、点赞数只加 1；但没抢到的那次请求返回的 `count` 可能还没算上这 1。点赞记录写入成功、点赞数更新失败时只记日志，仍返回成功；`count` 返回计数字段当前的值，没有加上这 1，和之后读到的一致。

**错误情况**：参数不合法返回 `code: 400, msg: "参数错误"`；目标不存在或不是正常状态（隐藏、删除的题目，审核中、已删除的评论）返回 `code: 400, msg: "点赞对象不存在"`；数据库出错返回 `code: 500, msg: "服务器内部错误"`。

## POST /api/v1/interaction/unlike 取消点赞

**鉴权**：强制登录

**请求体**：

```JSON
{
  "target_type": 1,
  "target_id": "q001"
}
```

**响应**：

```JSON
{
  "code": 0,
  "msg": "success",
  "data": {
    "liked": false,
    "count": 256
  }
}
```

响应结构与点赞相同，`liked` 恒为 `false`，`count` 是取消点赞后目标的总点赞数，来源同点赞。

当前用户取自 token。把有效的点赞记录 `status` 置为 0，记录保留。接口是幂等的：只有点赞状态从有到无时，目标的点赞数才减 1，最小为 0；没点过赞或已经取消过时什么都不改，也不新建记录，直接返回当前点赞数。点赞记录更新成功、点赞数更新失败时只记日志，仍返回成功；`count` 返回计数字段当前的值，没有减掉这 1。

**错误情况**：与点赞相同。
